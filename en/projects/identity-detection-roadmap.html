A not-yet-started learning track for Microsoft Entra ID, KQL and detection-engineering fundamentals.

Research question

How should testable identity scenarios and detection hypotheses be designed before running a lab?

Method and tools

  • Use the planned SC-300 lessons as the foundation for identity and access-control reasoning.
  • Later define an authorized scenario with expected telemetry and verification criteria.
  • Document relevant KQL queries and testable results only after practical exercises have actually taken place.

Tools: Planned: Microsoft Entra ID · KQL · Defender XDR · Microsoft Sentinel (conditional)

Observations and evidence

Not started as an independently validated security case. No implemented Sentinel analytics rule or confirmed detection result is claimed.

Limitations

Some Defender and Sentinel features require suitable licensing and may incur Azure costs. No tenant changes or paid resources are authorized without separate approval.

What I learned

A learning roadmap expresses intent; it is not evidence of deployed detection capability.

Next verification step

After Security+ V8 and AZ-900, reassess the start of SC-300 and then establish the prerequisites for a safe KQL lab.
