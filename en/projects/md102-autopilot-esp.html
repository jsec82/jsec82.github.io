Windows Autopilot & Intune

A practical Windows 11 lab covering user-driven enrollment, Microsoft Entra join and Intune management.

In progressNov 2026Evidence-based case — no simulated results

A practical Windows 11 lab covering user-driven enrollment, Microsoft Entra join and Intune management.

Research question

How can Windows enrollment, identity trust and management policy behavior be evidenced separately?

Method and tools

  • Reviewed Autopilot targeting, enrollment restrictions and ESP settings read-only.
  • Completed Windows 11 user-driven setup with the selected test account.
  • Inspected join status and PRT observations through dsregcmd, alongside the device record in Intune.
  • Later reviewed compliance and configuration results without claiming untested control enforcement.

Tools: Windows 11 · Microsoft Intune · Windows Autopilot · Entra ID · dsregcmd

Observations and evidence

Learner-reported: AzureAdJoined = YES, DomainJoined = NO and AzureAdPrt = YES; the device appeared as Microsoft Intune-managed. Later observations included Compliant and a Test profile showing Succeeded.

Limitations

Several other configuration profiles showed Conflict. The root cause remains unidentified. Actual ESP completion, application enforcement and the effectiveness of all security settings remain unverified.

What I learned

Device enrollment, a compliance label and actual security-control enforcement represent different evidence levels.

Next verification step

Identify specific conflicting settings through a time-boxed read-only review, then plan safe, per-control effect validation.
